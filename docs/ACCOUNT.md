# 帳號與片庫（0.6.0／build 16）

## 原生手機驗證碼登入

「我的」提供原生 SwiftUI 登入介面：國碼、手機號碼、取得驗證碼、簡訊驗證碼與登入。手機號碼和驗證碼由使用者直接在 App 輸入，透過官方 HTTPS API 傳送；不經自建服務，也不要求在聊天中提供驗證碼。

使用者自行閱讀官方[使用者協議](https://reading.snssdk.com/wap-hongguo/dr-agreement-v2.html)及[隱私政策](https://reading.snssdk.com/wap-hongguo/dr-privacy-v3.html)，自行勾選後才能按「取得驗證碼」。不預先勾選，不在開啟頁面時自動發碼。重新發送有倒數，改號碼會取消舊操作並解除驗證碼綁定；關閉介面會取消操作並清除輸入的手機號碼及驗證碼。

官網登入方案已由實機確認不適用：iPhone 官網顯示下載導流頁，沒有可用登入入口。因此 0.4.1 的 App 登入不使用 WKWebView 或官網登入按鈕。來源要求上行簡訊時，只顯示本次挑戰提供的收件號碼／內容，由使用者自行發送，再明確按下繼續驗證；不代發、不輪詢猜驗證結果。其他來源拒絕或無法完成的驗證會明確顯示，不能當作登入成功。

登入以 SMS／後續驗證回覆中的一致、非零 UID 與有效會話憑據為依據。登入時註冊的匿名 App 裝置身分與 Cookie／Token 隨同一個登入會話保存；帳號同步沿用它，不重新註冊另一個身分。讀取通用的匿名使用者資訊不算登入驗證。Keychain 還原後會先檢查本地憑據／有效期限與 UID 結構，再由實際帳號 API 判斷會話是否仍有效；不將本地檢查描述為遠端驗證成功。

登入會話只存於這部 iPhone 的 Keychain；不放在 UserDefaults、片庫 JSON、來源查詢參數、播放請求或 CDN 請求。手機與驗證碼輸入不落檔。匿名影片取源保持獨立。登出先移除鑰匙圈中的登入資料，取消進行中的帳號請求，再切回本機片庫；不假造未確認的官方遠端登出接口。

## 本機與帳號片庫

- 本機片庫與各個帳號、各個播放來源分開儲存。舊版 `library.v1` 收藏與觀看紀錄可遷移，原資料保留。
- 片庫使用受 iOS 資料保護的原子 JSON 寫入，保留上一份有效快照；資料無法解析時不以空片庫覆蓋。
- 記錄最近觀看的分集、秒數、時長與觀看時間，也分別保存各集進度。單集看至 98% 只表示「本集看完」，不宣稱整劇看完。
- 收藏與觀看變更先存本機，按劇集合併待同步操作。只有官方確認請求成功，且本機操作編號仍相同後才移除；較舊回覆不能清掉較新的操作。操作編號由本機管理，不宣稱官方提供冪等鍵。
- 登入不自動合併訪客資料；使用者可在帳號片庫選擇「匯入本機片庫」，確認後將收藏及觀看紀錄加入帳號的待同步隊列，本機原片庫仍保留。
- 觀看紀錄的移除／清除是本機隱藏，保留防止舊雲端快照復活的記號；沒有假造官方刪除歷史接口。取消收藏則是明確的帳號待同步操作。

帳號同步先檢查會話的 UID 與有效期限，再取得雲端片庫、合併並上傳待同步變更。新的雲端觀看時間可以取代較舊本機進度；只有確認完整的收藏清單才以缺席判定遠端移除。頁數或來源覆蓋不足會保留既有資料。切換帳號、來源或登出會取消請求；先前播放器仍只能把最後進度存回原本的片庫。

## 片庫搜尋、排序與多選整理

0.6.0 的收藏與觀看紀錄可在本機搜尋目前已載入的片庫資料，支援繁簡中文、全半形與大小寫比對，多個詞須同時符合；搜尋不向官方發出片庫查詢，也不改寫顯示名稱。歷史保留「全部／本集未完／本集看完」篩選，可依最近觀看、最早觀看、名稱或本集進度排序；收藏提供片庫原有順序與名稱正反序，不把原有順序宣稱為收藏時間。

搜尋與排序由單一背景 worker 執行，搜尋輸入防抖 180ms；最多一筆運算及一筆最新待處理快照。回覆綁定片庫、來源、條件及資料世代，舊結果不會套用到新片庫。

按「編輯」以作品 ID 多選；全選只涵蓋目前搜尋／篩選符合的結果。純排序保留選取，切換片庫、來源、歷史／收藏、搜尋文字、進度篩選或片庫資料更新時會清除選取；處理中暫停選取及批次提交。執行前的確認對話框列出數量與本機／帳號片庫，凍結選取 ID 與當時的帳號／來源；確認時若已換片庫或搜尋結果尚未就緒，就不會套用。

- 批次移除歷史只移除這部 iPhone 上的紀錄，保留收藏與防止舊快照復活的記號；不刪除官方歷史。
- 本機片庫取消收藏只改本機；帳號片庫會明確提示加入待同步變更並同步至紅果，觀看紀錄會保留。
- 整批在載入完成後依原片庫順序，以一次本機狀態變更套用；無效輸入整批拒絕，已不存在的項目略過。官方收藏同步仍逐筆確認，不宣稱官方提供批次原子操作。

未選項目的操作 UUID 與手動重試標記保持原樣。明確取消已選收藏是新的使用者意圖，使用新的操作 UUID；舊回覆不能清掉新操作，失敗時沿用既有手動重試與落盤保護。

## 背景保存與最後進度

0.5.0 將整庫 JSON 編碼、讀取、有效快照備份與原子檔案寫入移到串行背景流程。每個帳號／來源的快照有遞增版本，等待寫入的多次進度可合併為較新快照；晚到的舊版本不能覆寫新資料。儲存失敗會顯示錯誤並保留待保存狀態，不以空片庫替換原檔。

初始載入也是背景工作。載入完成前的收藏、清除及進度操作依原來的帳號／來源排隊，先等既有資料載入才套用；載入失敗即停止變更。快速切換來源時，舊載入結果不能顯示於新片庫，舊播放器的最後進度仍留在原來的片庫。

暫停、離開播放器及 App 離開前景會觸發 `flush()`：等已排操作完成載入，再等待最新進度真正寫入。App 背景切換使用有限的系統背景執行時間；這不是強制結束、斷電或所有裝置情況下的零遺失保證。合成測試已驗證舊寫入尚未完成時，flush 仍會等待較新的最後進度。

## 未確認操作與手動重試

0.4.3 為每筆收藏／進度操作保存 `retryRequired`。每次嘗試在網路寫入前，先將標記設為 true 並原子保存，再等待寫入回覆；只有確認成功且操作 UUID 完全相同，才移除該筆。取消、逾時、程式中斷或重新啟動後，未確認操作仍需手動重試，不會因記憶體快取消失而自動重送。

0.5.0 的背景保存不改變這項要求：帳號寫入必須先 `await` 對應版本或較新快照落盤，儲存失敗就不能送出該次寫入。這個屏障與一般進度合併分開處理，不只把儲存工作排入背景就繼續送出請求。

自動同步略過這些操作，繼續處理其他尚未嘗試的變更；失敗的首筆不會擋住後面的獨立操作，也不占用自動批次名額。只有使用者按「同步並重試」，才明確允許重新提交並重設該操作在服務中的失敗快取。重試選取本身不先清除持久標記；若只有需手動重試的操作，不會持續安排自動同步迴圈。

「我的」會顯示需手動重試的筆數，即使重新開啟 App、暫時沒有錯誤文字仍會保留。這表示回覆尚未確認，不保證官方沒有收到上一筆。新的使用者變更使用新的 UUID；舊回覆不能移除新操作。補齊海報或合併遠端進度也不會默默解除重試限制。舊版片庫缺少此欄位時，預設為 false，保留原有待同步資料。

## 大型片庫的載入

自 0.4.2 起先提交已取得的觀看紀錄，再提交收藏，讓清單能先出現。缺少的劇名、海報與分集資料在背景以最多四筆並行補齊，每輪最多 50 部、總期限 45 秒；不讓逐筆詳情請求阻塞整份片庫。尚缺資料會明確標示載入中，可於下次同步繼續補齊。

0.5.0 改為公平輪替：選過的項目移到隊尾，失敗後由 30 秒逐步退避至最多 300 秒；前 50 筆持續失敗也不會一直擋住後面的有效作品。每輪有獨立任務識別，舊任務的回覆與結束處理不能清除新任務或回填其他片庫。詳情快取受 48 部、10 分鐘 TTL 與合計 12,000 集的上限約束，換來源或帳號會清除。

補資料只改既有項目的作品資訊，不改收藏狀態、進度、時間、待同步操作編號或重試限制。每輪最多選取 20 筆收藏及 10 筆觀看變更；自動批次只選取可自動提交的操作，其餘保留排隊。有未選取且符合該輪讀取條件的操作時才安排後續自動批次，已需手動重試的項目不形成循環。片庫 JSON 上限 32 MiB，超限會顯示錯誤並保留原檔。

## 官方資料契約

帳號請求限定 `https://api5-normal-lq.fqnovel.com`，沿用原生登入的 App 7.3.5.32 profile、裝置身分、Cookie 與 `X-Tt-Token`；註冊時不帶帳號憑據。沒有切換主機、繞過來源驗證或重新登入的隱藏回退。

| 用途 | 方法與路徑 |
| --- | --- |
| 發送手機驗證碼 | POST `/passport/mobile/send_code/v1/` |
| 手機驗證碼登入 | POST `/passport/mobile/sms_login/` |
| 上行簡訊後驗證 | POST `/passport/upsms/verify/` |
| 讀觀看紀錄 | GET `/reading/bookapi/read_history/list/v` |
| 讀收藏 | GET `/reading/bookapi/bookshelf/video/list/v` |
| 收藏／取消收藏 | POST `/reading/bookapi/bookshelf/video/update/v` |
| 寫觀看紀錄 | POST `/reading/bookapi/read_history/update/v` |
| 寫續播位置 | POST `/reading/bookapi/read_progress/upload/v` |

進度由 App 的秒數換算為接口要求的毫秒。兩個進度寫入均確認成功才完成待同步操作；只成功第一個時會保留待同步狀態及明確錯誤。模糊失敗不暗中重送同一操作；使用者按「同步並重試」後可明確重試。來源拒絕、格式改變或登入失效會在「我的」顯示，資料仍保留於手機。

**歷史實機證據（0.4.2）：** 當次已在實體 iPhone 完成原生手機驗證碼登入、更新後會話還原、片庫讀取，以及收藏新增／取消、實際播放後進度寫入的成功狀態。尚未在另一部裝置的官方 App 獨立核對進度；這些紀錄不代表後續版本已重新執行真人帳號網路或硬體驗證。

0.6.0 最終完整測試包含 Core 279 項／35 個 suites（278 通過、1 項可選快照略過），以及直接編譯 App Controller／保存流程的 AppSupport 12 項／1 個 suite，全部通過；合計登錄 291 項，290 通過、1 略過，記錄於 `build/core-0.6.0-validated-tests.log`。片庫新增 8 項瀏覽／批次政策測試與 4 項 Controller 整合測試，驗證單次提交、延遲載入、原 scope 隔離與較新使用者意圖。測試使用合成資料、注入的儲存與 metadata 載入器，沒有登入真人帳號、發送簡訊、操作真實 Keychain 或寫入官方片庫；不代表這些新畫面或真人帳號批次操作已完成當版實機驗收。

歷史 0.5.0 最終測試為 Core 245 項與 AppSupport 8 項，合計 253 登錄、252 通過、1 略過，記錄於 `build/core-0.5.0-validated-tests.log`。0.4.4 核心回歸為 199 項、23 個 suites，198 通過、1 略過；0.4.3 為 190 項、22 個 suites，189 通過、1 略過。合成測試不能代替其他真人帳號或地區的驗證；地區輸入清單不保證能收到簡訊。簽署裝置建置、安裝與當版實機狀態集中記錄於 [TESTING.md](TESTING.md)，核心與 AppSupport 測試指令見 [TESTING-CORE.md](TESTING-CORE.md)。
