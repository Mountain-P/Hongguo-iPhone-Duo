# 內建漸進播放（0.11.0／build 27）

## 0.11.0 播放交接、題材與滿版

2026-11-08 更新。試看按「追這部」後，仍透過最新詳情及片庫紀錄確認正式播放目標；符合下列條件才將同一個 AVPlayer／AVPlayerItem 的所有權交給正式播放器：同劇同集 ID、同一 item、snapshot／當前位置／正式目標彼此相差不超過 2 秒、片庫與來源 revision 及畫質一致、場景在前景、item 已就緒且沒有定位中，交接年齡小於 60 秒。交接只能接受一次；取消、失效或不符合條件便釋放舊交接並走正常準備流程，不跨片庫復活。這不保證每次都能重用，也不承諾免除來源等待。

一般播放器上下換集時保留上一集的實際影格，直到新影片 surface ready 且初始 seek 完成，再移除轉場畫面；錯誤、取消與遲到回呼仍綁定當次路由，不以固定延遲猜測新畫面已可見。

試看新增頁內滿版，隱藏原生 Tab／狀態列與控制資訊，不另建播放器。點空白只切換控制顯隱；中央按鈕控制播放／暫停。雙指縮放限制在 0.5–3 倍，選單另有放大、縮小、還原及完整比例／填滿，畫面縮放不改媒體秒數或上下換劇規則。長按獨立倍速提示與既有旋轉重錨保護保留。建置、GUI 及手機的實際驗收狀態見 [TESTING.md](TESTING.md)。

本機推薦加入來源真實題材的明確多／少推薦偏好，以及跨頁末兩部題材交錯，詳見下方「本機題材排序與理由」。既有畫質選源、取消、預取及快取預算不變。

## 0.10.0 轉場、換集與精細進度

0.10.0 的試看交接使用暫存影格：只在點「追這部」時從既有 item 的 video output 複製一幀，縮至長邊最多 960 像素，不額外取源或 seek、不寫入磁碟。暫存圖只配對同劇、同集且位置差不超過 2 秒的正式路由；正式播放器的初始 seek 完成與原生 surface ready 都成立後才移除，並以影格 UUID 回報父頁清除其參照；舊路由回報不能清掉新影格。取不到有效畫面時沿用正常轉場，錯誤、取消、離頁或不同分集均清除；此設計減少畫面中斷，沒有宣稱縮短來源網路等待。0.11.0 在此基礎上加入上節的有條件播放器重用。

一般播放器的上下滑採獨立狀態：垂直超過 90 pt 且超過水平距離 1.2 倍才可提交，畫面顯示目標集數、進度與放開提示；越過門檻給輕觸感。最後位置退回門檻內就取消，首末與未開放相鄰集只提示，長按加速與細調不會同時換集。

進度條從目前 playhead 累積水平位移。手指位於軌道上方 50／100／150 pt 時依序改為 ½／¼／¹⁄₁₀ 靈敏度；切換靈敏度本身不跳時間。拖動僅預覽時間，正常放開才提交一次 seek；系統取消、背景、離頁或換集不提交。VoiceOver 可每次前後調整 5 秒。

## 0.9.3 一般播放器上下滑換集

一般全螢幕播放器在未進入長按時，超過短距離移動且方向明確的上滑切到緊鄰下一集，下滑切到緊鄰上一集；成功切換一律從零播放，不套用該集舊續播位置。第一／最後集的邊界只顯示提示並保留當集；緊鄰集未開放時也只提示，不跳過它尋找其他可播放集。這是手動換集規則，不改既有自動下一集設定。

長按成立後，上下滑優先處理 2 倍速鎖定／解除，不同時換集。同頁試看仍以上下滑切換作品，不套用一般播放器的換集手勢。換集及邊界訊息使用頂部約 2 秒的獨立提示，不喚回整組 HUD；0.9.2 的獨立倍速提示與控制列顯隱保留持續適用。原有點空白處顯隱、中央播放／暫停與手動速度選單維持不變，當版結果見 [TESTING.md](TESTING.md)。

### 試看尺寸變更後重新對齊

旋轉後頁高改變但未重新錨定時，卡片無法通過嚴格對齊檢查，會呈現半截卡片並失去播放資格。0.9.3 保留原最後停穩的劇集 ID，依新 viewport 重新對齊，幾何確認完成後才恢復啟播及互動；縮放過渡期間阻擋誤點。重錨採限次捲動，新尺寸變更會取消舊任務，不重設片單、詳情快取或既有媒體身分，也不將手動暫停改為自動播放。修後 GUI 驗證另依 [TESTING.md](TESTING.md)，本段不代表已完成畫面驗收。

## 0.9.2 倍速提示與控制列分離

正式播放及同頁試看的長按 2 倍速開始／放開，都保留整組 HUD 原本的顯隱狀態，不再因加速操作喚回控制列。一般播放器的鎖定及解除鎖定也沿用這項規則，頂部獨立提示呈現加速／鎖定狀態；試看提示移出 HUD 的 opacity 範圍，控制列已隱藏時仍可看到倍速狀態。

點影片空白處顯示／隱藏控制、中央播放／暫停與手動速度選單維持原有操作，長按門檻及一般播放器的上下滑鎖速手勢不變。0.9.1 的換劇交接與現有畫質、預取限制持續保留；本版測試、GUI、建置及手機結果見 [TESTING.md](TESTING.md)，不因文件更新視為已驗收。

## 0.9.1 換劇取源共用

非強制刷新時，同劇集、內容類型及畫質的進行中取源工作可由預取與前景共用。每位讀取者獨立取消；最後一位取消才撤銷 producer，已取消的遲到結果不寫入快取。強制刷新不加入舊工作，只有最新有效寫入者可更新快取。保留 120 秒／16 筆來源快取，另限制最多 16 個尚未結束的 producer、每個最多 32 位讀取者；已取消但未回應的 worker 仍佔名額。

試看以最後停穩的卡片為播放目標，保留相鄰預取直到當次首幀實際播放後再準備下一部。只共用詳情與取源；progressive 的索引及首段 HTTP 準備仍可能各自執行，沒有宣稱請求位元組減半。既有單播放器、1 MiB 首段及網路／電力門檻不變。控制對照及實網解碼結果見 [TESTING.md](TESTING.md)。

## 0.9.0 候選擴源與手動重試

`RecommendationDiscoveryService` 僅包裝試看目錄；搜尋、詳情與播放仍委派原 service，正式取源及帳號界線不改。第一頁只等原目錄，後續最多混入一次同類榜單／新劇快照。真人與 AI 使用各自新劇類型，漫劇不發出新劇請求。

補充來源各最多 40 部、合計 80 部，每頁最多混入 6 部；主來源耗盡時每頁最多補 20 部。輸出每頁最多 100 部、100 頁，seen IDs 最多 10,000；主來源 buffer 最多 200 部，provenance 最多 512 筆，model 只保留目前 queue 的來源文字。來源標示與個人化題材理由分開，不修改原有 tags 或 badge。

背景來源有 8 秒期限；後續頁可等待同一工作的剩餘時間，不重複建立補源請求。續體協調器讓逾時／取消結束等待，不以 TaskGroup 等待不合作 provider；晚回覆不能直接寫入 adapter。主來源耗盡後不再請求不存在的主頁。

`ContinuePlaybackModel` 保留失敗的 immutable launch intent；人工重試核對原 context，再讀最新分集及紀錄。白名單暫時失敗與選擇期間紀錄變更才保留重試。取消、背景、來源變動或新操作清除舊意圖；被取消的舊 caller 在任何 mutation 前返回，舊工作的 defer 不能清掉新工作。試看滑到另一部也撤銷舊重試。只有成功開啟的正式播放器沿原 scope handler 寫入進度。

App 首次啟動採用「內建播放」。首頁、劇場搜尋與劇集詳情直接連到來源平台；這些頁面的海報瀏覽不會準備影片，按播放後才發出取源與索引請求。0.4.4 的「試看」在同一頁連續垂直捲動，每劇佔一個可用畫面，停穩對齊後才試播第一集。不需要使用者填播放服務網址，也不需要 Mac 持續開機。影片索引準備好即可開始，剩餘資料依播放與拖曳位置取得。「我的」集中觀看歷史、收藏與設定。

## 0.8.2 推薦及控制細節

不感興趣就地移除明確隱藏的卡片，保留來源分頁、其他媒體及詳情快取；舊回應需再次套用最新隱藏清單。推薦 model 與 queue 使用可控的非同步回應測試，實際換頁另以模擬器驗證。

試看位置與正式紀錄只有在作品、原始分集、完成狀態及解析後目標相同，且秒差不超過 2 秒時，才省略選擇並接試看位置。完成一集跳下一集、末集重播與不同原始分集不能只因解析後都為零秒而合併。

正式與試看 HUD 的 transport、載入及緩衝變化只更新自動隱藏排程，不改使用者已隱藏的狀態；等待提示獨立顯示。點空白處、中央播放、手動選速、錯誤與輔助使用各自沿用原有控制規則；0.9.2 的長按及鎖速操作只更新獨立倍速提示。

`PreviewWatchQualification` 以單調時鐘累計保留卡片的有效播放時間，通常 10 秒；已知短片則採片長九成、最低 1 秒。250 ms 採樣並在資格邊界結算，超過 1 秒的未知採樣間隔不計；只在目前卡、前景、已顯示首幀、實際播放且沒有緩衝／載入／錯誤時累計。倍速或 seek 的媒體位置不能充作時間，標記每張卡最多回報一次；這仍是本機試看排除用途，不是正式觀看歷史或推薦喜好。

## 0.7.0 一鍵續播、來源畫質與海報快取

首頁最近觀看與「我的」歷史提供手動一鍵續播。`ContinuePlaybackModel` 先讀取最新分集，再依 `PlaybackContinuation` 選擇原位置、已播完後的下一個可用集，或末集的零秒重播。準備前後均核對目前片庫、來源版本與前景／分頁資格；已移除的歷史或遲到回覆不能開啟播放器，瀏覽清單本身不會準備影片。

`NativePlaybackQuality` 提供「自動（最佳可用）」與「省流量」，設定保存在本機，由 `AppModel` 注入 `NativeCatalogService`、`NativeSourceResolver` 與 bundled runtime。「自動」保留既有最佳可用選源策略；「省流量」從來源 model 的真實尺寸選擇較低畫質 H.264／HEVC 相容版本，仍驗證網址與解密資訊。只有單一版本、尺寸無法確認或較低版本無效時，回退至實際可播放來源，不虛構 720p／480p 選項。這是 MP4 來源選擇，並非隨網路變動的 ABR；設定只作用於內建播放的下次取源，不即時替換目前影片。設定變更會使後續詳情／試看的載入 context 失效，不改帳號或片庫範圍。

取源快取及可重用首段的鍵均加入畫質偏好；即使省流量回退至與自動模式相同的來源，也分開保存。正式連播與試看預取沿用各自捕捉的 service，使用相同偏好與既有流量／取消限制。`NativeMediaStream.variant` 提供 `NativeMediaVariant`，只含偏好、編碼、來源畫質標籤、尺寸與回退標記，不含播放網址、內容金鑰或身分；工具可觀察實際準備的版本。

海報改用共用 `PosterImagePipeline`，依顯示尺寸在背景產生縮圖，合併同來源下載；取消一個消費者不取消其他消費者。預設解碼縮圖快取最多 32 MiB／80 筆，排程最多三個並行請求，使用記憶體快取而非離線圖片庫。32 MiB 是快取上限，不是整個 App 或顯示中圖片的記憶體上限。目前沒有與舊版 `AsyncImage` 作同條件對照，不宣稱實際捲動、記憶體或網路用量的改善幅度。

## 0.6.1 暫停與音訊中斷

片尾通知到達時會重新核對目前 item、載入世代、前景狀態與最新播放意圖；使用者已暫停、App 進背景或音訊中斷時，不會因晚到通知自動換集與取源。正常自然播畢、允許連播且仍有播放意圖時，維持自動下一集。

`AVAudioSession` 中斷開始與舊音訊裝置移除，會接到既有暫停／進度保存流程，同時撤銷長按加速與預取。中斷結束不自動播放，使用者再按播放才繼續；一般裝置加入與類別改變不誤判為耳機移除。observer 的生命週期世代會擋住 stop／start 之間晚到的通知。依據 Apple 的[音訊中斷處理](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions)及 [AVFoundation 音訊恢復行為](https://developer.apple.com/library/archive/documentation/Audio/Conceptual/AudioSessionProgrammingGuide/HandlingAudioInterruptions/HandlingAudioInterruptions.html)；本輪本機注入測試與真耳機／來電的驗證界線另記於 [TESTING.md](TESTING.md)。

## 0.6.0 正式連播、偏好與診斷

正式播放器在播完、沒有下一集或關閉自動連播時，再按播放會先定位零秒。定位回呼綁定同一分集與操作世代；等待期間暫停、換集或另一次定位，舊回呼不能自行恢復播放。手動選擇的正常倍速與自動下一集設定保存在本機；長按加速和鎖速不寫入正常倍速，試看固定關閉自動下一集，也不覆寫正式播放的偏好。

正式內建播放接近結尾時，沿用 `NativePlaybackPrefetch` 為下一個可用分集準備首段。觸發窗口約為剩餘 12 秒的實際播放時間，會按目前倍速換算；目前影片須至少有約三秒緩衝，最後不足三秒時則須完整緩衝剩餘部分。只有實際播放、允許連播、非昂貴／非受限網路且未開低耗電時才預備；暫停、資料不足、向後定位、背景化、換集或關閉連播會取消。仍受既有 1 MiB 媒體準備預算與有界首段快取限制，不建立第二個 AVPlayer，也不承諾所有網路都可無縫接集。

「我的 → 設定 → 播放診斷」最多保存 80 次不含內容身分的數值測量：準備到首幀就緒、播放中等待與自動重試次數；另顯示目前記憶體占用與溫度，不逐次保存資源快照。自動重新取源沿用同一次起播時鐘；恢復期間替換 item 的內部暫停不會把中斷時間漏掉，使用者明確暫停則結束等待。原片重播使用獨立 `.replay` 測量，定位完成只記 ready，不冒充新的解碼首幀。離開或暫停後停止五秒資源採樣；清除測量不改片庫。

診斷不接受片名、劇集 ID、播放網址、Cookie 或帳號，不自動上傳。實機的裝置電量變化只在連續未充電超過一分鐘後顯示，包含系統及其他 App 的耗電；各次播放／暫停之間不沿用舊電量窗口，不能把這個差值當作 App 單獨耗電。模擬器明確顯示無法代表 iPhone 效能或耗電。

另訂閱本機 [MetricKit](https://developer.apple.com/documentation/metrickit) 系統報告，只保留日期、CPU 時間、記憶體與捲動卡頓等白名單數值。系統報告通常按日提供，可能涵蓋整個 App 和不同版本；沒有收到報告不代表已完成效能驗證。app 的經過時間量測用途列在 PrivacyInfo 的 SystemBootTime `35F9.1`，數據只在本機使用，依據為 Apple 的[必要原因 API 說明](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitypereasons)。本輪實際建置、連播與量測界線見 [TESTING.md](TESTING.md)。

## 流程

1. `NativeCatalogService` 讀取官方目錄與劇集 `vid_list`，確認分集屬於目前劇集；網頁預覽的 `accessible_episode_cnt` 不作為內建來源的選集上限。
2. `NativeSourceResolver` 在本機 JavaScriptCore 執行隨 App 附帶的固定版本簽章程式。原生 URLSession 處理網路，CommonCrypto／CryptoKit 處理密碼演算法，zlib 處理註冊資料壓縮。這個簽章 runtime 只執行隨包程式。
3. 依目前取源契約先嘗試獨立匿名 GET；沒有可用模型才進入有次數與時間上限的 POST 復原。不同流程的匿名身分與 Cookie 分開；來源明確拒絕立即停止。成功片源以分集／content type／畫質偏好為鍵快取 120 秒、最多 16 筆；fresh 會重新取源，取消或失敗不寫入快取。這個影片取源流程不使用帳號會話或固定裝置憑證。
4. `NativeProgressiveMedia` 先抓取前 256 KiB，檢查前置 ftyp／moov，需要時只補索引至 moov 結尾加 16 bytes（最多 8 MiB），以及缺少的 CENC auxiliary 小範圍（最多三輪、8 MiB）。`NativeMP4.prepareStream` 建立可按任意 offset 處理的串流解密計畫，完成後立即返回，不等待整集下載。
5. App 與 macOS 工具共用 `HongguoPlayback.NativeMediaAssetLoader`，以公開 AVAssetResourceLoader API 將 `hongguo-native` asset 的讀取請求交給 `NativeMediaStream`。串流按需取得 512 KiB 區塊，處理 CENC／sample entry，使用 8 MiB 記憶體 LRU；每個串流重用 URLSession，最多兩筆 Range 同時下載。同一區塊的並行讀取共用一筆下載；取消一個讀取者不影響其餘讀取者，全部取消才取消該區塊請求。
6. 系統 AVPlayer／AVPlayerLayer 播放按需提供的資料，自適應畫布支援完整畫面與填滿螢幕。一般全螢幕播放器的 NavigationStack 提供原生工具列，倍速、快轉、選集及續播由原生狀態管理。同頁試看直接嵌入影片表面與輕量控制，不建立額外的播放器導覽頁。

Range 必須回傳精確的 206、Content-Range 與資料長度，檔長及來源提供的 ETag／Last-Modified 在串流中保持一致。只接受核准的 HTTPS CDN，轉址逐跳驗證；401／403 立即停止。來源以 200 忽略 Range 時會明確回報不支援，不會默默改成整集下載。索引／aux 準備總期限為 30 秒。

`NativeMediaStore` 的完整單集準備保留作明確對照與測試，並非預設播放或自動 fallback。漸進流程的區塊快取位於記憶體，不提供離線片庫。取源、索引與解碼錯誤分別保留，不以「連線成功」當成「可播放」。

### 0.5.0 的重用、預取與恢復

`NativeProgressiveMedia` 可重用已準備的串流，鍵包含分集、完整片源 URL、內容金鑰、codec、來源品質與 User-Agent，0.7.0 再加入畫質偏好；不同來源或偏好不共用。有效期為 30 秒，最多兩筆，準備時保留的 header／aux 資料合計上限 2 MiB。每筆串流另有最多 8 MiB 的區塊 LRU，因此 2 MiB 不是總記憶體上限。fresh 取源不命中舊項目，過期或來源驗證失敗不重用；401／403、Range／格式拒絕或來源 validator 改變會阻止後續讀取已快取的片段。清除可重用快取不取消正在播放的讀取。

`NativePlaybackPrefetch` 同時只管理一部相鄰首集的預取，不建立 AVPlayer 或音訊會話。媒體索引／aux 的請求位元組上限為 1 MiB；這個限額不包含目錄、劇集 metadata 或取源 API 的 JSON。超出上限就略過預備，不改成下載整集，也不阻止之後正常點播。預取結果可供正常播放重用；滑動、背景、離開分頁、開啟詳情／偏好及來源切換會取消舊預取。省電模式、昂貴或受限網路與尚未連線的路徑不啟用推測性預取；記憶體警告會清理預取快取。

`PlaybackRecovery` 只對已識別的暫時網路中斷、逾時與可重試伺服器錯誤自動重新取源一次。取消、401／403、來源拒絕、不支援的格式和未知錯誤不盲目重試。恢復沿用重載前的播放意圖；使用者暫停或進入背景後，遲到的 ready 回呼不應自行恢復播放。

## 觀看與倍速操作

首頁沿用劇場規格的 adaptive 直式海報網格，欄數依可用寬度自動調整，採自然垂直捲動；海報以 fit 完整顯示。點海報進入詳情，按「開始觀看」才準備並以 fullScreenCover 開啟獨立播放器，主 Tab 與首頁網格不透出。在播放器換劇會先返回海報，由使用者再次點播；同一劇集內的「自動下一集」仍可獨立設定。

播放器從 0.2.1 起使用 `playerFillsScreen.v2` 偏好，新偏好首次預設等比裁切填滿，可切回完整比例並保存選擇。0.8.0 的正式播放及同頁試看，單點影片空白處只切換控制顯示／隱藏，不切換播放狀態；播放／暫停由中央按鈕明確操作，亦保留 VoiceOver 的播放／暫停動作。控制資訊透明覆蓋影片，播放時可閒置隱藏，影片保持全畫布，不為控制列縮小。完整比例模式的留白由影片長寬比自然產生。原生控制列的位置由系統依 Duo 姿態決定；長按加速與鎖速規則維持如下。

根畫面使用「首頁／試看／劇場／我的」原生 TabView；一般全螢幕播放器自帶 NavigationStack 與有名稱、symbol 的 `.toolbar` 項目。Duo 外螢幕與內螢幕橫向可使用側欄，內螢幕直向的原生列則在上下方。一般播放器的「更多」提供選集、下一集及自動續播；同頁試看提供首集播放控制、收藏、推薦偏好、「追這部」及獨立詳情入口，非滿版時保留原生分頁列。點按與 hover 分別處理。原生列的實作依據見 Apple [Raise the bar with iPhone Duo](https://developer.apple.com/videos/play/tech-talks/111462/) 與 [Designing for iPhone Duo](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo)。

0.2.4 的影片資訊採輕透明圓角框，片名／集數一列，slider／時間一列，最大寬度 560 pt，以玻璃材質呼應原生底部工具列。iOS 26+ 使用 `.glassEffect(.regular)` 與圓角矩形；較舊系統使用 ultraThinMaterial，啟用 Reduce Transparency 時改用不透明背景。資訊框隨 `controlsVisible` 同步隱藏，包含原有閒置自動隱藏；顯示與隱藏都只覆蓋影片，不重算影片尺寸。

以下換集及鎖定／解鎖手勢屬一般全螢幕播放器；同頁試看只有長按暫時加速，沒有上下滑鎖速：

- 一般播放器未進入長按時，明確上滑／下滑切換緊鄰下一集／上一集；短距離移動不觸發，成功切換從零播放，邊界或未開放只顯示頂部短提示。
- 長按影片至少 0.35 秒，暫時以 2 倍速播放；放開恢復選單選定的速度。
- 長按後上滑 60 pt，鎖定 2 倍速，放開仍維持。
- 鎖定後再長按並下滑 60 pt，即時解除鎖定並恢復選定速度。也可點「2 倍速已鎖定」提示解除。
- 從倍速選單選取速度會解除長按加速與鎖定；再長按暫時加速後，放開回到該選單速度。暫停時選倍速維持暫停，選速度不會自行開始播放。進入背景會取消暫時長按，已提交的鎖定保留。

長按成立後的上下滑只處理鎖速，不再同時觸發換集；一般播放器在同劇內換集，與試看上下滑換另一部作品分開。

自 0.9.2 起，以上長按開始／放開、鎖定及解除鎖定（包含點鎖定提示解除）都不喚回整組 HUD，頂部倍速提示獨立顯示；試看的提示也不受 HUD opacity 隱藏。原先控制列顯示就保留顯示，原先隱藏就保留隱藏，手動速度選單的控制行為不變。

`PlaybackSpeedState` 以獨立核心狀態保存正常速度、長按與鎖定；其行為測試與實際 Duo 手勢驗收分開記錄，最新畫面及手勢結果見 [TESTING.md](TESTING.md)。

## 推薦試看

「試看」使用目前目錄的真實片單；0.8.0 在本機為新候選批次排序，不使用未確認的官方帳號個人化推薦 API。只有使用者選取該分頁才載入；每劇是一張佔滿可用 viewport 的原生垂直分頁卡片，上滑至下一部、下滑至上一部，畫面隨手指移動。拖曳及減速期間不啟動新影片，停穩且對齊的卡片才取得唯一啟播資格。尚未準備的相鄰卡片顯示海報；已載入的當前卡在拖曳期間暫停、保留最後影格，回到同頁時可恢復原播放意圖。

0.8.1 將推薦 pager 延伸到容器底部，原生 Tab 背景透明，影片及海報採填滿畫布。保留原生側欄與分頁裁切，每頁仍使用同一個實際 viewport 高度，不另加底部頁高。影片控制資訊、共用的準備／取消列與錯誤提示各自使用底部安全距離，避讓原生列而不縮小影片；GUI 與手機結果以 [TESTING.md](TESTING.md) 為準。

首次啟播的劇從可用的第 1 集零秒開始；短時間滑回仍保留的卡片，可沿原位置繼續。第一集缺失或未開放時可重試或換劇，不改播第二集。每卡只接收一集，播畢暫停，不自動連播或換劇；進度 callback 不寫入片庫，因此不覆蓋既有續播位置。同頁卡片長按僅暫時 2 倍速，上下拖曳完整交給分頁。

0.5.0 的收藏沿用目前選定的本機／帳號片庫操作，與「已試看」標記分開。「推薦偏好」可調整公開目錄的內容類型、略過已試看的劇，並保存不感興趣的劇集 ID；這些偏好只作用於本機片單，不代表官方個人化推薦。偏好入口位於影片的可用區域內，避讓有效摺痕與鏡頭遮擋。

「追這部」先捕捉 `PreviewPlaybackSnapshot` 的劇集／分集 ID、位置與時長，暫停試看，再透過單一 `ContinuePlaybackModel` 讀取最新詳情，直接建立正式播放入口。snapshot 不落入正式歷史；同名作品不能代替 ID 匹配，分集已缺失或未開放會停止，無效時間歸零。試看完成依既有 98% 單集規則接下一個可用集，末集則零秒重播。

若目前片庫已有不同的有效正式進度，顯示「接續原進度」／「從試看位置看」及各自集數、時間，由使用者選擇。最新紀錄在詳情完成後讀取，選擇時再核對；期間紀錄變更或刪除就安全中止並要求重新操作，不自動重建選項。準備與接受選擇都檢查 owner、來源 revision、場景／分頁可見性、請求世代及取消；進度 factory 在最後 context 檢查後建立，只能寫回原 scope。

片名仍可進入該劇詳情。從詳情或正式播放器返回均保留卡片與捲動位置，等待手動「繼續試看」，不與正式播放器同時啟播。首頁與劇場的手動點播維持原行為。可見卡、來源與請求世代綁定；滑動、離開分頁、背景化及詳情導航會撤銷舊資格，遲到回覆不得回填。片單去重、分頁及 metadata／卡片快取都有上限。來源與分頁限制見 [DISCOVERY.md](DISCOVERY.md)。

### 本機題材排序與理由

`PersonalizedRecommendationProfile` 使用目前 owner／來源片庫的收藏、符合條件的保存位置及目前內容類型的明確題材偏好，搭配作品原有的真實 tags。收藏權重高於觀看紀錄；觀看紀錄須有合理時長、位置至少 30 秒且達單集一半，保存位置仍不是實際停留時間或喜歡的證明。泛用標籤不當作興趣；沒有足夠訊號或候選無匹配題材時，沿用來源順序，不從片名猜測。

試看先做來源驗證、去重及既有偏好排除，再只排序新到達的批次，保留正在播放及已存在卡片的位置。排序保留探索候選，跨頁以有效回應到達當下片單最後兩部的真實題材作交錯參考，減少批次交界連續相同題材；不是在請求開始時固定舊片尾。收藏／紀錄或明確偏好更新可供下一批使用，也會重算既有卡片的理由，但不重新排列目前片單；切換 owner 或來源會重置片單與 profile。

卡片選單僅列出作品實際提供的有效題材，可選多推薦或少推薦；少推薦降低排序，不硬性隱藏，不從單劇「不感興趣」推斷題材。每個片庫／來源／內容類型最多保存 32 題材，以雜湊 context 隔離，最多 8 份、總計 128 KiB；可逐筆或全部恢復中性。存取在串行背景工作進行，舊 context 的載入與操作不能套用到新片庫。

「因你收藏《…》」或最近觀看理由必須有實際共享標籤及仍存在的來源作品；「你選擇多看『題材』」則對應明確偏好，不假造收藏或觀看來源。作用域不符不顯示。profile 不含帳號憑據，也不傳送至推薦服務；這是本機輔助排序，不能描述為官方帳號推薦。原有內容類型、略過已試看及單劇不感興趣設定仍適用。

## 自訂服務

「我的 → 設定 → 播放方式 → 自訂播放服務」為選用功能。網址與口令完成協定及目錄驗證後才儲存，並切換為服務播放。這個模式仍使用 Range／Bearer 的原生 ResourceLoader；與預設內建流程分開。切回「內建播放」即可恢復獨立執行。

## 帳號與觀看紀錄

在「我的」可以選擇本機或已登入帳號的片庫。登入不會自動上傳訪客紀錄；需明確選擇匯入，才把副本加入帳號待同步隊列。各來源與帳號分開儲存，播放器建立時綁定原片庫，切換帳號後的遲到回覆不能寫入另一個帳號。

觀看位置先保存於手機。帳號同步先以 `validateForLibrary` 檢查本地會話、帳號與有效期限，再用該會話及同一 `AccountAppDevice` 讀取官方紀錄、合併並提交待同步收藏與進度；這個本地檢查不是已證實的獨立線上驗證。會話是否仍有效，由實際 Cloud 請求判定，登入失效或來源拒絕會顯示錯誤。只成功一部分、來源拒絕或格式改變時保留待同步狀態。清除觀看紀錄是本機隱藏；取消收藏是明確的帳號操作。簡訊登入、MFA、收藏寫入與跨裝置同步各自依真人實測記錄判定，App 建置與合成測試不代表後續帳號操作均已獲接受。詳細契約見 [ACCOUNT.md](ACCOUNT.md)，當版結果見 [TESTING.md](TESTING.md)。

明確執行真實來源與 macOS 影片解碼檢查（目前工具同樣使用 progressive 與共用 loader）：

```sh
swift run NativePlaybackCheck SERIES_ID EPISODE_NUMBER
swift run NativePlaybackCheck --startup SERIES_ID EPISODE_NUMBER
swift run NativePlaybackCheck --seek SERIES_ID EPISODE_NUMBER
swift run NativePlaybackCheck --startup SERIES_ID EPISODE_NUMBER --quality automatic
swift run NativePlaybackCheck --startup SERIES_ID EPISODE_NUMBER --quality dataSaver
```

不加旗標時，工具按需取得並完整解碼一集的影片與音訊；`--startup` 只驗證準備與第一幀，`--seek` 直接從影片 70% 位置取得第一幀。所有模式可加 `--quality automatic|dataSaver`，省略時採 automatic。工具輸出影格數、音訊 buffer 數、時長及所選來源的安全畫質資訊，不印出片源簽名網址、內容金鑰或匿名身分。

0.7.0 在同一部 102 集劇集的第 4 集，各作一次 Mac／Debug 的實網取源及 `AVAssetReader` 首幀解碼：

| 模式 | 實際來源 | MP4 總長度 | 準備／首個解碼影格 |
| --- | --- | --- | --- |
| 自動（最佳可用） | HEVC，1080p，1080 × 1920 | 7,506,580 bytes | 3.18／5.72 秒 |
| 省流量 | HEVC，360p，360 × 640 | 2,436,342 bytes | 2.44／2.71 秒 |

兩次均成功準備、解密並解出首幀，來源未使用回退。檔案總長度是該來源回報的 MP4 大小，不是首幀實際下載量；各一次的網路與解碼樣本只能證明這一集存在較低畫質且可解碼，不代表所有作品都有低畫質、手機起播更快或一般化的流量節省比例。安全摘要為 `build/quality-0.7.0/validation.txt`。

0.2.0 的 progressive 基準使用同一部 102 集劇集的第 4 集分次實測：startup 準備 2.82 秒／首幀 3.10 秒；完整串流解碼全部 89.79 秒、2,244 影片影格及 825 音訊 buffer，首幀 1.98 秒／全流程 7.9 秒；70% seek 準備 1.66 秒／首幀 2.09 秒。均不使用播放服務，數值反映各次網路與快取狀態。原先整集準備路徑的 31.2 秒／745 個音訊 buffer 僅保留為歷史對照。

上述數據是 macOS 核心與 AVFoundation 解碼證據。另有 0.2.0／build 3 的真機簽署安裝與播放畫面，且使用者已確認有聲音。0.2.1／build 4 已安裝，但首頁點播入口曾遇 scrollPosition 取消競態；0.2.2／build 5 的固定格數首頁屬中間版。0.2.4／build 7 的劇場式首頁與輕透明資訊框、0.3.0 的附加選劇 metadata 均保留版本紀錄。0.4.2／build 12 已完成真機 Debug 與未簽署 Release 建置。各版 Release、簽署安裝及原生帳號登入／片庫的最新驗收狀態見 [TESTING.md](TESTING.md)。真機長按手感與長時間播放／耗電仍待驗證。
