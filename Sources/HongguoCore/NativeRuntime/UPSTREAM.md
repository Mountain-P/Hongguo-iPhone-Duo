# On-device playback runtime

The five original modules in `PlaybackAssets` (`app-source.js`, `playback-device.js`, `playback-recovery.js`, `sm3.js`, `download-quality.js`) were copied from this project's GPL-3.0-only Backend modules as integrated on 2026-11-06. Their original source is jackotom/hongguo-drama commit `2bab5cf15529ece7bfe657f93c6d1a2a4a17fef0`; existing signing and anonymous-registration provenance is preserved in each source header and the bundled `NOTICE.txt` / `LICENSE.drpys.txt`. `app-source.js` now has narrowly scoped account and phone signing exports; its existing signature primitives and playback functions are unchanged. `playback-device.js` adds an explicit account-only 7.3.5.32 registration option while preserving its default playback profile. The full project GPL license is bundled as `LICENSE.GPL-3.0-only.txt`. Backend provenance and local changes are described in `Backend/server/modern/UPSTREAM.md`.

The request ordering, branch-2 signing and playback profile were checked against the user-provided Quest source and aston314/hongguo-tv commit `36508246eeca2cf5ef1f29f7f17f8e985d50ae2e`. No Go implementation was copied. Synthetic vector facts in `Backend/tests/fixtures/signing-vectors.json` are reused by the native runtime tests, with no live credentials, device identities or signed URLs.

The Buffer compatibility layer is pinned to these official npm tarballs. The original MIT licenses for buffer and base64-js and the BSD-3-Clause license for ieee754 are included alongside their source:

- `buffer` 6.0.3: https://registry.npmjs.org/buffer/-/buffer-6.0.3.tgz
- `base64-js` 1.5.1: https://registry.npmjs.org/base64-js/-/base64-js-1.5.1.tgz
- `ieee754` 1.2.1: https://registry.npmjs.org/ieee754/-/ieee754-1.2.1.tgz

`source-sha256.json` records the bundled JavaScript bytes. `runtime.js` and all Swift adapters are new local GPL-3.0-only code. The app evaluates only this bundled source using JavaScriptCore; it does not download executable JavaScript or include Node, npm, a browser engine, Go, or FFmpeg as a playback dependency.

`runtime.js` supplies the subset of CommonJS, Buffer, URL, timers, Promise HTTP and AbortSignal used by the bundled modules. Native adapters replace `node:crypto` with CryptoKit hashes, Security random bytes and CommonCrypto AES-CBC/CTR/ECB; replace `node:zlib` with system zlib; and replace Axios with ephemeral URLSession transactions. The cipher shim buffers its update inputs until final, which preserves the bundled registration and URL-decryption call sequences; it is not a general replacement for every Node streaming API.

Each resolution has its own serial JavaScriptCore queue, anonymous identities, request tasks, cancellation and 30-second JS budget plus a 31-second native watchdog. Network redirects are returned to the module's own allowlist checks. URLSession does not retain credentials, cookies or cache state. Non-200 status is preserved before reading any error body, so binary or oversized 401/403 responses remain terminal. Model bodies are capped at 2 MiB while receiving; API requests require HTTPS, port 443 and the fqnovel.com / snssdk.com domain trees. Final media additionally requires an approved qznovelvod.com / fqnovelvod.com / douyinvod.com CDN domain and a supported H.264/HEVC codec.

The playback path does not use an account, reward, unlock or purchase flow. Optional account-library operations are described below and remain separate from playback. CENC media transformation is implemented separately by the native media store, and system AVFoundation handles decoding. The JavaScript runtime's source success alone does not establish full media decoding or physical iPhone playback.

## Recent-release metadata

`new-releases.js` adapts the category request body and row metadata from `src/native/hongguo-app-new.js` and the public JPEG cover normalization from `src/native/hongguo-app-catalog.js` at jackotom/hongguo-drama commit `2bab5cf15529ece7bfe657f93c6d1a2a4a17fef0` (GPL-3.0-only). Its local changes select one of the demonstrated真人/AI genres, preserve large series IDs before JSON parsing, cap each snapshot at two sequential 50-item pages and eight seconds, validate advancing cursors, propagate cancellation and source denials, and remove search fallback and process-global caching. Swift provides a 60-second, two-category cache. A snapshot is limited source coverage, not a complete calendar or a cross-category chronological ranking. A fresh JavaScript context owns its anonymous metadata profile; it neither registers a playback identity nor shares one with playback.

## Native App account and phone authentication

`native-phone-auth.js` and `account-library.js` are local GPL-3.0-only adapters. Existing GPL registration and signing primitives are reused, including branch-2 F13/Medusa already present in `app-source.js`. The explicit account registration option in `playback-device.js` uses App 7.3.5.32 and returns its own device ID, install ID, CDID, client UDID and open UDID. It does not alter default playback registration. The phone service persists that dedicated App identity, and the cloud service reuses exactly that identity rather than registering another device.

GPL reference sources inspected for request/registration provenance:

- charlie901208/HGTV commit `b97e8cc69473db9400aa991898e392e3227d1c21`, `android/core/src/main/kotlin/com/hgtv/star/core/PhoneLogin.kt`, `Signer.kt`, `DeviceRegister.kt`; its earlier `feat/phone-login` branch no longer exists at the time checked.
- tsukiyo-zero/hongguoTV commit `70edafffc635d691d667ac1e6936c3ba827da9cf`, `kotlin-tv/core/src/main/kotlin/com/hongguotv/core/PhoneLogin.kt`, `Signer.kt` and `CloudAccount.kt`.
- jackotom/hongguo-drama commit `2bab5cf15529ece7bfe657f93c6d1a2a4a17fef0`, `src/native/app-source.js` and `src/native/account-session.js`, for the existing licensed primitives and earlier read-only account work.

These Kotlin phone flows use another host/profile and explicitly lacked complete real-device SMS-login acceptance. They are provenance, not proof that the new LQ flow works. The LQ 7.3.5.32 request fields, full-mode branch selection, international mode-4 behavior, exact favorite/progress JSON shapes and millisecond units were independently re-expressed from the user-provided Quest reference. Its `core/cmd/hongguotv/cloud.go` is byte-identical to aston314/hongguo-tv commit `36508246eeca2cf5ef1f29f7f17f8e985d50ae2e` (Git blob `cf66a0ffa9d20750458ec3ea84c4dc2a2c265c17`). No Go signing implementation was copied. The mode-4 standard RC4 implementation is new JavaScript, checked against the independent synthetic vectors in the reference's `testdata/passport-international-v124.json` (package SHA-256 `d8e8eaf5cc6f5fa61101be90bb2e520fa83248dab46239f66d02cc5c10bcc13b`); the vectors contain no live login capture.

Phone signing admits only POST `/passport/mobile/send_code/v1/`, `/passport/mobile/sms_login/` and `/passport/upsms/verify/`. Mainland requests use full branch-2 signing; other supported country codes use mode 4. No endpoint fallback, automated SMS resend, invented logout endpoint or guessed remote UID-validation endpoint is introduced. Passport's successful login response and actual session credentials are required by Swift; reading-user-info success is not authentication. The website-login path is no longer used for native account synchronization.

Cloud signing admits only history GET `/reading/bookapi/read_history/list/v`, favorites GET `/reading/bookapi/bookshelf/video/list/v`, and POST `/reading/bookapi/bookshelf/video/update/v`, `/reading/bookapi/read_history/update/v`, `/reading/bookapi/read_progress/upload/v`. All use HTTPS `api5-normal-lq.fqnovel.com`, profile 7.3.5.32 and the login session's device identity. Cookies and optional `X-Tt-Token` are sent only to that exact account host; redirects are forbidden. Account credentials never reach registration, playback or media CDNs. POST signatures cover exact outgoing bytes, including precision-preserved numeric history IDs.

Registration is bounded to eight seconds, each phone operation to fifteen seconds, and each library operation to twenty seconds. History is bounded to ten pages / 5,000 rows, favorites to 5,000 rows, read caches to thirty seconds, and recent local mutation receipts to 256 IDs. Invalidation cancels operations. A same-ID success is reused locally; an ambiguous failure requires explicit reset before retry. These are local acknowledgements, not upstream idempotency keys. Both progress POSTs must be confirmed before success; partial acceptance remains an error. Missing pagination evidence yields an incomplete snapshot rather than an authoritative empty library. No background synchronization starts in the Core service.

Offline tests establish signature-vector compatibility, wire formats, bounds, credential confinement and cancellation. They do not establish actual SMS delivery, successful real-account login, session lifetime, or cloud read/write acceptance. No SMS or private-account request was made while implementing this runtime.
